# GPT3的训练数据与训练过程

**GPT3 在过滤后的 Common Crawl、WebText2、两个图书语料及英文维基百科的混合数据上进行自回归预训练；八种规模均训练 3,000 亿词元，但数据来源的抽样比例不按其大小分配。**高质量小语料被重复抽样，大规模网页和 Books2 则不到一遍。预训练更新参数，少样本评估只改变输入上下文。

本文依据 [[Language-models-are-few-shot-learners-GPT3.pdf]] 第 2.2–2.3 节、表 2.1–2.2、附录 A–B 整理。下一词元预测的定义与训练损失复用 [[生成式预训练]]，本篇集中记录 GPT3 自己的数据、优化和复现条件。

## 从“更大语料”到“更有用的训练混合”

Common Crawl 的规模已接近一万亿单词，足以支持作者训练大模型而不重复更新同一序列。但作者发现，未经筛选或仅轻度筛选的数据，平均质量不及经过更多整理的数据集。因此，GPT3 的数据准备包含三个互相配合的步骤：按高质量参考语料过滤网页，进行文档级模糊去重，再加入高质量参考数据。

作者从 2016–2019 年的 41 个按月划分的 Common Crawl 分片下载文本。过滤前为 45 TB 压缩纯文本，过滤后为 570 GB；正文近似记为 4,000 亿 BPE 词元，表 2.2 列为 4,100 亿。它们是同一论文中的不同精度表述，不需要强行统一。

WebText2 是 GPT2 WebText 的扩展版本：抓取链接的时间更长，最早在论文所引用的规模规律工作中描述。GPT3 论文没有在这里给出 GPT2 式的相同时间截断，因此不能把 [[GPT2的WebText数据集]] 中的“2017 年 12 月”直接移植到 WebText2。Books1、Books2 来自互联网，原文没有公布足以重建完整语料的书目清单。

## 过滤与去重的具体做法

附录 A 的自动过滤器使用逻辑回归。特征来自 Spark 标准分词器和 HashingTF。正例来自 WebText、Wikipedia 和网页图书等筛选语料，负例来自原始 Common Crawl。分类器为每个网页文档给出分数，再按随机规则决定保留：

```python
np.random.pareto(α) > 1 - document_score
```

当且仅当上述条件满足时保留文档，作者取 $\alpha=9$。这一设置优先保留高分文档，同时让部分分布外文档仍有机会进入数据集；$\alpha$ 的选择用于匹配分类器在 WebText 上的分数分布。它不是把所有低于某个固定分数的网页一律删去。作者报告，这种重加权改善了多种分布外生成文本样例上的损失。

模糊去重使用 Spark 的 MinHashLSH，设置 10 个哈希，输入特征与分类器相同。作者在各数据集内删除与其他文档高度重叠的文档，并从 Common Crawl 中模糊移除 WebText；整体上，数据集大小平均下降约 10%。模糊去重检测的是近重复，不保证所有改写、引文和跨语种对应都被消除。

筛选器学习“像参考语料”的统计特征，不是事实正确性的审核器。网页质量提高、重复减少与测试集不泄漏，是相关但不同的问题。

## 数据源大小不等于实际训练占比

下表完整保留论文表 2.2 的数值。billion 为十亿，300B 为 3,000 亿。

| 数据源 | 可用词元数量 | 训练混合权重 | 训练 300B 词元时经过的轮数 |
| --- | ---: | ---: | ---: |
| Common Crawl（过滤后） | 410 billion | 60% | 0.44 |
| WebText2 | 19 billion | 22% | 2.9 |
| Books1 | 12 billion | 8% | 1.9 |
| Books2 | 55 billion | 8% | 0.43 |
| Wikipedia | 3 billion | 3% | 3.4 |

“训练混合权重”是训练期间从某数据源抽取的样例比例。它不是各数据源占整个原始语料的百分比。作者有意更频繁地抽取认为质量较高的来源：较小的 WebText2、Books1、Wikipedia 被看过多遍，Common Crawl 与 Books2 少于一遍。这是以少量过拟合风险换取更高质量训练材料的选择，并非完全避免重复数据。

> [!note] 原表精度与口径
> 权重列相加为 101%，原文没有提供足以重建全部未舍入值的细节；仅用显示的数量与权重，不能精确反推出每项轮数。保留原表是核验依据，不能擅自改写成合计 100% 的新比例，也不能用未经说明的再归一化值声称复现了作者设置。

## 训练一个序列时如何安排文档

所有模型使用完整的 2,048 词元序列训练。较短文档会被打包到同一序列，以提高计算效率；文档之间用特殊的文本结束词元分隔。作者没有为同一序列中的不同文档增加特别的隔离注意力掩码，而是让模型根据分隔符推断两侧内容通常不相关。

这与“只从单篇长文档截取 2,048 词元”不同，也与“每个文档只与自身位置做注意力”不同。它仍使用自回归语言模型的基本条件关系，不能把“没有特别文档掩码”理解为没有因果掩码。

数据在一个轮次内无放回抽样，到达轮次边界后可以再次抽取。无放回不代表每个数据源永远只读一遍，表 2.2 已显示小数据源被重复使用。

## 优化器、学习率与批次

附录 B 给出以下共同设置：

| 项目 | GPT3 论文设置 |
| --- | --- |
| 优化器 | Adam |
| Adam 参数 | $\beta_1=0.9$，$\beta_2=0.95$，$\epsilon=10^{-8}$ |
| 梯度裁剪 | 全局梯度范数上限 1.0 |
| 权重衰减 | 0.1 |
| 学习率预热 | 前 3.75 亿词元线性预热 |
| 学习率衰减 | 在 2,600 亿词元跨度内余弦衰减到初始值的 10% |
| 后续学习率 | 2,600 亿词元之后维持初始学习率的 10% |
| 批次预热 | 从 32k 词元线性增加到完整批次 |
| 批次预热时长 | 依模型规模，在前 40–120 亿训练词元内完成 |
| 总训练量 | 每种模型均为 3,000 亿词元 |

较大模型通常能用更大批次、但需要更小学习率。作者在训练中测量梯度噪声尺度，用于指导批次选择。表 2.1 中批次以词元计，不能理解为文档数量。

| 模型 | 完整批次（词元） | 原表学习率 |
| --- | ---: | ---: |
| GPT-3 Small 125M | 0.5M | $6.0\times10^{-4}$ |
| GPT-3 Medium 350M | 0.5M | $3.0\times10^{-4}$ |
| GPT-3 Large 760M | 0.5M | $2.5\times10^{-4}$ |
| GPT-3 XL 1.3B | 1M | $2.0\times10^{-4}$ |
| GPT-3 2.7B | 1M | $1.6\times10^{-4}$ |
| GPT-3 6.7B | 2M | $1.2\times10^{-4}$ |
| GPT-3 13B | 2M | $1.0\times10^{-4}$ |
| GPT-3 175B | 3.2M | $0.6\times10^{-4}$ |

全部模型在 Microsoft 提供的高带宽集群中的 V100 GPU 上训练。为了避免显存不足，作者同时使用矩阵乘法内部和网络层之间的模型并行。论文没有报告足以重建完整运行的 GPU 数量、训练时长、全部并行分组和通信调度。

## 训练计算量不是实际训练天数

附录 D 为最大模型估算总训练计算量约 $3.14\times10^{23}$ 次浮点运算，即约 $3.64\times10^3$ petaflop/s-days。一个 petaflop/s-day 对应 $8.64\times10^{19}$ 次浮点运算，表示以每秒 $10^{15}$ 次运算持续一天的总量；它不是“训练了这么多天”，也不是价格或电量单位。

估计将每个活跃参数、每个词元的前向计算近似为一次乘法和一次加法，再乘以 3 计入反向传播，总计约 6 次浮点运算。附录为简化计算忽略注意力运算，并称其对所分析模型通常占总计算量不到 10%。因此，这是按参数、词元及计算假设得到的近似量，不能当作实际测得的全部设备功耗或碳排放。能源讨论的进一步边界见 [[GPT3的局限与社会影响]]。

## 训练数据与评估数据重叠的问题

预训练数据来自公开网络，测试题、上下文或答案可能已在网上存在。作者尝试移除与全部评测开发集和测试集的重叠，但过滤程序出现错误，部分长文档未正确处理。训练成本使重新训练不可行，所以论文另行检测污染，并对结果可能受影响的数据集作标记或不予报告。

因此，“不做任务微调”不能推出“模型从未在预训练中见过相似题目或测试文本”。污染检测也不能直接把任意文本重叠认定为答案泄漏：阅读理解题的背景段落与题目、答案应分别判断。具体检测和证据边界见 [[GPT3的基准污染与记忆分析]]。

## 复现时仍需核对什么

论文提供了训练目标的继承关系、架构规格、主要数据来源、数据混合表及核心优化设置，足以解释研究方法；但未完整公开全部图书材料、Common Crawl 保留文档、过滤器拟合产物与系统配置。仅照着表格选相同参数，不能保证得到相同模型。

评估也需要单独复现：任务提示、示范抽样、候选评分、解码方式和划分都可能影响分数。预训练批次与少样本 $K$ 分属两个阶段，不应把增加上下文例子解释为增加训练轮次。评估规则与代表性证据见 [[GPT3的任务设置与实验结果]]。
